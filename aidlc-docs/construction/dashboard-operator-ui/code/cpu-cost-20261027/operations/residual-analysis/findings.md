## Smallest follow-up candidate

Design and test **bounded transient recovery for `source_changed` only** in the shared read service. Treat a failed generation as unusable, re-discover and fully validate a fresh generation, and coalesce the finite retry allowance across concurrent sessions. Keep the same worker/admission/resource limits, 4s foreground return, 2s freshness, 30s stale age, and one page watcher. A finite per-logical-read attempt/deadline budget must survive page rerenders and error-TTL expiry; retries must not become four independent session loops. Waiting/backoff must not block the sole worker from useful sibling work. Exhaustion and every other terminal reason retain explicit manual Refresh behavior. This is a proposed narrow change to the current source_changed terminal policy, not an implemented correction or a promise that a fixed retry count will finish during arbitrarily long writes.

Minimal acceptance scenarios, using deterministic source-change barriers rather than timing guesses:

1. Cached valid activity, exactly one source mutation during verification, then stable input: bounded recovery publishes the newly fully verified payload automatically; no stale-as-complete and no cache-age reset on failure.
2. Repeated sequential snapshot replacements during two failed attempts, followed by stable input within the agreed retry budget: all four clients coalesce and recover with one worker/four admissions/one watcher per page. Compare full canonical output and coverage.
3. Persistent churn beyond the budget, malformed JSON, and resource-budget failure: finite work and terminal explicit Refresh; neither watcher nor normal error-TTL polling resets an exhausted logical retry sequence indefinitely.
4. Source changes at each verification point, including atomic replacement, directory membership and checkpoint proof: none publishes a mixed/unverified generation. Clock/window semantics stay exact.
5. Slow snapshot retry with independent jobs: completed siblings retain their original ages and revalidate after 2s; retry backoff does not monopolize the worker or add unbounded queue metadata. Same-query ABA/close/manual-retry paths remain safe.

Add only bounded allowlisted attempt/verification-phase and queue/build-duration diagnostics if needed to verify this recovery. Keep account/path/query representations out of logs. The present generic projection stage cannot identify whether a failed attempt spent its time parsing, checkpointing or awaiting another job.

No additional benchmark or tests were run for this read-only diagnosis. No rollback is justified specifically by these records: full source/output verification remains intact, the previous CPU reduction remains locally measured, and the residual terminal-policy limitation predates that optimization. Production acceptance remains failed until separately corrected and re-qualified.
